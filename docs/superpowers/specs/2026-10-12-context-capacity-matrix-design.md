# Strata 启动器：多档上下文容量与完整 Benchmark 设计

日期：2026-10-12  
范围：独立维护的 `launcher/`；不修改 Strata 官方引擎、服务、模型配置或全局设置。

## 目标和口径

用户选择若干现有档位（32K、64K、128K、256K、384K、512K），验证某模型在本机上实际可用的上下文长度。“可用”不等于服务能启动：必须发送接近该档上限的真实长输入，在文本前、中、后位置准确找回信息并生成回答，重复验证且没有请求失败。报告给出各档的实际输入 token 数和独立结果；只在通过这些条件时称该档“已验证可用”，不推断未测的中间档位，也不把 512K 配置上限描述为 512K 实际输入。

被勾选的档位是明确的测试集合，不自动补齐中间档。例如只勾选 128K、512K，就只测试这两档。复选框显示顺序固定为从小到大；“第一个勾选的”指这个显示顺序中数值最小的档位，不取决于点击先后。

## 用户界面

现有“模型上限”单选下拉替换为上述六个复选框，并保留“沿用原配置”作为无勾选时的默认行为。新增默认关闭的“逐档完整测试”开关，以及与其他测试项目并列的“上下文容量探测”复选框。

- 开关关闭：即使勾选多个档位，也只按显示顺序运行第一个勾选档位；其余显示为已选择但本次未执行，开始前的确认框明确列出有效档位。没有勾选任何档位时沿用模型原配置，与当前默认路径相同。
- 开关开启：对每个被勾选档位分别启动独立的临时模型配置，逐档运行当前勾选的全部 Benchmark 项目，而非只运行容量探测。至少需要勾选一个档位；开始前展示模型数 × 档位数 × 轮数，以及长上下文测试可能耗时/占用大量内存的警告。
- 只有勾选“上下文容量探测”，才进行近上限的正确性验证并计算“已验证可用”的档位。开关可与该项目独立使用：未勾选容量探测时，各档只是执行所选常规项目，报告不得给出容量通过结论。勾选容量探测但没有选择任何档位时，启动前要求选择档位。
- 现有“输入长度”4K/32K/128K/256K 仍控制基础性能和原有 Needle 项目；新的容量探测采用所运行档位的近上限长度，不受这组输入长度复选框限制。
- 保存设置时记住档位勾选状态和开关状态；旧版设置仍按原有单个 `max_context` 恢复为一个勾选档。旧设置缺省时使用“无勾选、开关关闭”的兼容路径。

## 运行编排与隔离

沿用现有 Benchmark 的预检、专用端口、配置快照、进程所有权、安全停止、状态文件和报告目录。将一次运行组织为“模型 × 有效档位 × 轮次”。每一档的临时快照只覆盖 `--max-context` 与对应的 RoPE/YaRN 参数；大于原生 256K 时使用当前已有的实验性 YaRN 规则。绝不写回源模型 JSON 或官方 `settings.json`，也不自动把最大通过档应用为日常启动设置。

每个模型与档位组合必须具有独立且短的结果标识、配置快照文件名、日志名和报告分组；不能复用现有单一 `model_id` 混合不同档位的样本。报告同时保留原模型标识、所选档位、有效 `--max-context`、配置哈希及引擎版本。无勾选的兼容路径继续使用现有标识与快照命名，以免旧报告或默认运行行为无故变化。

常规项目按档位运行，但某些用户所选“输入长度”大于当前档位可容纳值。对每档逐项计算输入加输出预留：不适用的性能/原 Needle 用例记为“档位不适用”，继续运行同档其他适用项目；不能把它计入失败或静默略过。缓存对话若估算超出当前上限，也必须明确标为不适用。报告分别列出要求的输入档位、实际执行项和跳过原因。

若某档因内存/显存不足或服务启动失败，记录该档失败并安全清理；在同一模型上比它更高的已勾选档位标为“未执行：低档资源失败”，避免重复触发同类资源故障。单个召回失败不推断更高档必然失败，仍继续后续已选档。用户取消时保留已完成的逐档数据，未开始的档位标为取消/未执行。无法确认子进程安全停止时，沿用现有的阻断机制，不继续启动下一个配置。

## 容量探测判定

容量探测由 `launcher/benchmark` 内的独立工作负载实现，沿用官方 `tools/needle_bench.py` 的前/中/后隐藏信息方法，但不修改官方工具。每档在 10%、50%、90% 三个位置各运行两次，使用不同的可精确匹配的随机码，关闭思考与提示缓存，保持确定性采样。请求预留输出空间，记录服务返回的真实 `usage.prompt_tokens`、响应、正确性、耗时、结束原因与进程遥测。若真实 token 数不足该档上限的 90%，先在安全预留范围内调整文本并重试；仍不足则记“未达到目标长度”，不得算通过。测试文本、目标码及回答保存在该次报告目录，便于复核。

六次请求都成功、真实输入达到阈值、三个深度均两次命中、没有截断/超时/服务异常时，该档才标为“已验证可用”。任一条件未满足为“未通过”或“证据不足”，分开展示原因。最高已验证档只是所选且实际测试档位中的最大者；旁边始终显示该档的真实 prompt token 范围，不宣称模型的理论或绝对极限。该测试衡量此类信息召回任务，不等于所有长上下文任务的质量保证。

## 数据、报告和兼容

命令行新增可重复或逗号分隔的档位参数和“逐档完整测试”标志，并保留旧 `--max-context` 的单档语义以兼容现有调用。UI 与 CLI 共用同一解析/校验逻辑；重复档、未知档、空的逐档选择都在预检阶段拒绝。运行清单记录原始勾选档、有效档、逐档开关、项目、每档适用项与容量判定规则版本；逐条 JSONL 记录保留模型/档位/深度/重复次数和实际 token 证据。

HTML、Markdown、`summary.json` 与分享 SVG 均按模型和档位展示结果，不把不同档位的吞吐量、内存峰值或召回率混为一个中位数。新增“上下文容量”表：配置上限、真实输入范围、六次召回、失败/跳过原因、峰值内存、每档状态和最高已验证档。旧报告缺少这些字段时仍能打开，显示原来的单档数据，不凭空补造容量结论。报告继续注明内存采样与 TTFT 的现有局限。

## 验收和非目标

先用离线单元/结构测试验证勾选排序与开关、旧配置兼容、按档位展开、适用性跳过、容量阈值与六次判定、失败后资源清理、取消和分档报告；再运行现有 Python/PowerShell 回归与分享包检查。最后如获用户许可，在本机真实模型上做一个低档到高档的小规模试跑，核对实际 token、正确率、内存、进程退出和可见报告。离线测试不能代替真实 GPU/模型验收。

本功能不自动调整日常模型上下文、不修改官方测试工具、不做无上限搜索，也不将通过的 Needle 类任务称为所有任务的质量认证。
